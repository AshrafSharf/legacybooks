11.2 Greatest Common Divisor

Textbook pages 3–7

Let us look at a familiar problem: computing the greatest common divisor (gcd) or highest common factor (hcf) of two numbers. We have already learned different ways to solve this problem, using prime factorisation and other methods.

How can we solve the problem from the definition of gcd? How do we write down an algorithm for this?

The first step is to understand what is required and break down the problem into smaller pieces that we know how to solve.

  • We want the greatest common divisor of two numbers.
  • For this, we need to first compute the divisors of both numbers and note them down.
  • Once we have done this, we need to compare the two collections of divisors and find the largest number that is present in both collections.

11.2.1 Computing the Divisors of a Number

Suppose we want to compute \(\gcd(375, 825)\).

How do we find the divisors of 375? The divisors of a number are just the factors of that number. Clearly any divisor, or factor, must lie between 1 and 375. The simplest way to find the divisors is to check each number between 1 and 375 and see if it divides 375.

We also have to keep track of the divisors of 375 so that we can compare them with the divisors of 825. We can maintain each of these in a sequence, or a list. How do we create the list of divisors of a number? When we start, we do not know any divisors, so the list of divisors is initially empty. Every time we find a new divisor, we add it at the end of the list.

Here is how we can write down this algorithm to find the list of divisors of any number \(n\).

Algorithm to find the divisors of \(n\)

  1. Start with an empty list-of-divisors.
  2. For each number j in the sequence 1,2,3, … ,n
    • if j divides n, add j to the list-of-divisors.

Notice how we use names list-of-divisors and j to identify the values that we keep track of in this algorithm. If we do not use j to identify the number we are checking next as a possible divisor, it would be clumsy to describe what to do each time we find a divisor.

Running through an algorithm step by step is also called executing the algorithm. Let us execute this algorithm for a small number, say 18. We use square brackets to denote a list of values — for instance, [1, 4, 9, 16].

Let us see how this algorithm works for a small number, say 18.

  • Initially list-of-divisors is empty [ ].
  • 1 divides 18, so we update list-of-divisors to [1].
  • 2 divides 18, so we update list-of-divisors to [1, 2].
  • 3 divides 18, so we update list-of-divisors to [1, 2, 3].
  • 4 does not divide 18, so we leave list-of-divisors unchanged as [1, 2, 3].
  • 5 does not divide 18, so we leave list-of-divisors unchanged as [1, 2, 3].
  • 6 divides 18, so we update list-of-divisors to [1, 2, 3, 6].
  • 7 and 8 do not divide 18, so we leave list-of-divisors unchanged as [1, 2, 3, 6].
  • 9 divides 18, so we update list-of-divisors to [1, 2, 3, 6, 9].
  • 10, 11, 12, … , 17 do not divide 18, so we keep list-of-divisors unchanged as [1, 2, 3, 6, 9].
  • 18 divides 18, so we update list-of-divisors to [1, 2, 3, 6, 9, 18].

Thus, at the end of the algorithm we have divisors(18) = [1, 2, 3, 6, 9, 18]. Notice that the list is also in increasing order, because we checked for divisors systematically, from 1 to 18.

What is the basic step that we assumed in this algorithm? It is that we know how to compute when a smaller number divides a larger number.

If we go through the steps of the algorithm, we get the following answers.

  • divisors(375) = [1, 3, 5, 15, 25, 75, 125, 375]
  • divisors(825) = [1, 3, 5, 11, 15, 25, 33, 55, 75, 165, 275, 825]

Think and Reflect

Try to execute the algorithm to compute the divisors of 15, 135, and 775. How does the amount of work increase as the numbers grow?

11.2.2 Finding the Greatest Common Divisor

The second step in our procedure to find the gcd is to compare the lists of divisors of the two numbers and find the largest number that appears in both lists.

If we look through the divisiors of 375 and 825 above, we see that the answer is 75. What if the numbers were 54000 and 81000?

  • divisors(54000) = [1, 2, 3, 4, 5, 6, 8, 9, 10, 12, 15, 16, 18, 20, 24, 25, 27, 30, 36, 40, 45, 48, 50, 54, 60, 72, 75, 80, 90, 100, 108, 120, 125, 135, 144, 150, 180, 200, 216, 225, 240, 250, 270, 300, 360, 375, 400, 432, 450, 500, 540, 600, 675, 720, 750, 900, 1000, 1080, 1125, 1200, 1350, 1500, 1800, 2000, 2160, 2250, 2700, 3000, 3375, 3600, 4500, 5400, 6000, 6750, 9000, 10800, 13500, 18000, 27000, 54000]
  • divisors(81000) = [1, 2, 3, 4, 5, 6, 8, 9, 10, 12, 15, 18, 20, 24, 25, 27, 30, 36, 40, 45, 50, 54, 60, 72, 75, 81, 90, 100, 108, 120, 125, 135, 150, 162, 180, 200, 216, 225, 250, 270, 300, 324, 360, 375, 405, 450, 500, 540, 600, 648, 675, 750, 810, 900, 1000, 1080, 1125, 1350, 1500, 1620, 1800, 2025, 2250, 2700, 3000, 3240, 3375, 4050, 4500, 5400, 6750, 8100, 9000, 10125, 13500, 16200, 20250, 27000, 40500, 81000]

It is no longer so simple to just inspect the lists to find the largest element common to both of them! We need to do this systematically.

We compute a new list, the list of common divisors. As before, when we compute the list of divisors, this list is initially empty. For each divisor in the first list, we check if it belongs to the second list. If it does, we add it to the list of common divisors. Notice that 1 divides every number, so the list of common divisors will have at least one entry, 1.

Using this, we can compute the list of common divisors of 54000 and 81000, to be [1, 2, 3, 4, 5, 6, 8, 9, 10, 12, 15, 18, 20, 24, 25, 27, 30, 36, 40, 45, 50, 54, 60, 72, 75, 90, 100, 108, 120, 125, 135, 150, 180, 200, 216, 225, 250, 270, 300, 360, 375, 450, 500, 540, 600, 675, 750, 900, 1000, 1080, 1125, 1350, 1500, 1800, 2250, 2700, 3000, 3375, 4500, 5400, 6750, 9000, 13500, 27000].

Since we know that each list of divisors is in increasing order, it must be the case that the list of common divisors is also in increasing order. Hence the largest common divisor is the rightmost element in the list. In other words the gcd of 54000 and 81000 is 27000.

11.2.3 First Algorithm for gcd

Combining the steps above, we can write out a complete algorithm to compute the gcd of two numbers \(m\) and \(n\). This makes use of the earlier algorithm to compute the list of divisors of a number.

Algorithm to find \(\gcd(m, n)\)

  1. Let divisors-of-m be the list obtained by computing divisors(m)
  2. Let divisors-of-n be the list obtained by computing divisors(n)
  3. Start with an empty list common-divisors
  4. For each number x in the list of divisors-of-m
    • If x also appears in the list of divisors-of-n,add x to the list common-divisors
  5. Report the rightmost element of the list common-divisors as gcd(m,n)

When we execute this algorithm for \(\gcd(375, 825)\) we check whether each of the divisors [1, 3, 5, 15, 25, 75, 125, 375] of 375 appears in the list of divisors [1, 3, 5, 11, 15, 25, 33, 55, 75, 165, 275, 825] of 825. We see that 1, 3, 5, 15, 25 and 75 are in the second list while 125 and 375 are not. So we compute the list of common divisors to be [1, 3, 5, 15, 25, 75]. Since 75 is the rightmost element in this list, \(\gcd(375, 825) = 75\).
